# 批量测IP

一个安卓 App：批量测试 IP 和域名的延迟、下载速度，帮你从一堆目标里快速挑出能用的、快的。不只测 Cloudflare，任何 IP、域名都能测。

## 功能

- 批量输入：每行一个目标，最多 200 条（超过只测前 200 条）
- 输入格式：IPv4、IPv6、域名，可带端口（`IP:端口`、`域名:端口`、`[IPv6]:端口`），端口不限、默认 443；非法行跳过不计入
- 域名：先用系统 DNS 解析成 IP 再测，解析失败算失败
- 并发测试：10 条同时测，速度比逐条快很多
- 测速方法（分两条路，自动判断）：
  - Cloudflare 的 IP：连候选 IP、用域名做 SNI 握手，测 `www.cloudflare.com/cdn-cgi/trace` 取延迟和机房地区（先试你给的端口，再试 443、8443、2053、2083、2087、2096、80、8080、8880）；下载从 `speed.cloudflare.com` 下 1MB 实测，计时从开始读数据算起、不算握手时间，超时 30 秒，算 MB/s
  - 其他 IP/域名：直接 TCP 连目标 IP:端口测连接时间（毫秒），超时 3 秒，连不上再试 80 端口；下载试 HTTPS GET `https://目标/`（不行再试 `http://目标:80/`），最多读 2MB 或 5 秒，算 MB/s，测不到显示 `--`
- 地区：只有 Cloudflare 的 IP 从 trace 取机房地区码（us、hk、sg、jp…）；其他目标没有地区，显示 `--`，不查 geo 网站
- 成功标准：Cloudflare 的 IP 测出延迟就算成功；其他目标 TCP 能连上就算成功。下载速度照常测、照常显示，但不做筛选，结果里显示全部成功的，由你自己挑
- 结果显示：分两块。Cloudflare 的按地区分组（字母顺序），组内按下载速度从高到低；其他的按延迟从低到高排。每块没结果就写“暂无”
- 实时状态：测试时状态栏实时显示正在测哪个目标、已完成 / 成功 / 失败数
- 暂停：开始测试下方有暂停按钮，点一下停下剩下的，已测结果全部保留
- 导出结果：只导出成功的目标，格式为 `host:端口`（域名导出 `域名:端口`，IP 导出 `IP:端口`，IPv6 为 `[IP]:端口`），可复制、可分享
- 一键清空：清空输入、结果和状态
- 优选订阅（v1.3）：把测好的优选 IP 变成一条固定不变的订阅链接。先在订阅区粘贴一条 VLESS 节点链接当模板（只支持 VLESS WS+TLS），再把成功结果逐条或全部加入订阅列表（也可以手动粘贴 IP），点「更新订阅」就生成 Clash 和 sing-box 两份订阅，存在你自己的 SECRET Gist 里；订阅链接第一次更新后生成，此后永不换，只换里面的节点，填进客户端一次，一直能用。v1.3.1：模板链接端口后面带 `/`（如 `:443/?type=...`）也能识别。
- v1.4：界面改成左右两栏（左边测 IP，右边优选订阅，各自上下滚动）；节点模板和 GitHub 令牌改成单行输入框（值太长截断显示 …，长按可复制）；测试结果和订阅里的 IP 列表改成固定 10 行、框内滚动；订阅区新增「一键清空」（只清订阅列表）；更新订阅后自动用 no-cache 请求刷一次两条订阅链接的 CDN 缓存，客户端刷新立刻看到新 IP；界面换成深色面板。
- v1.4.1：启动崩溃捕捉——App 启动出错时不再直接闪退，而是把崩溃原因显示在屏幕上（并存下来，下次启动也能看到），方便定位问题。
- v1.4.2：修复 v1.4 一打开就闪退：根因是布局里两个内层滚动框写了 `android:nestedScrollingEnabled="true"`，这台手机上系统在构造 NestedScrollView 时会提前调用它、而内部辅助对象还没建好，直接空指针崩掉；删掉这个属性即可（NestedScrollView 默认就是开启嵌套滚动的，功能不变）。
- v1.4.3：界面改成标签页切换——顶部两个标签「🌐 测IP」「📡 优选订阅」，一次只显示一个板块、全屏宽度，另一个完全隐藏，默认显示测IP；两个标签字号、高度、内边距完全一致，图标跟着字号走所以大小也一致；目标列表输入框固定 30 行高、框内滚动；「从测试结果加入」列表固定 20 行高（960dp）、框内滚动；「订阅里的优选 IP」列表保持固定 10 行高（300dp）不动。
- v2.0：以 v1.4.4 为基础发布的正式版，功能与 v1.4.4 相同：加入行按钮「全部加入订阅」一行显示不换行；「从测试结果加入」列表 10 行高；两个「一键清空」分工明确——「更新订阅」旁边的清订阅列表，加入行旁边的只清本次测试结果。
- v1.4.4：对齐——「把本次成功结果全部加入订阅」缩短为「全部加入订阅」（6 个字，12sp 下一行放得下不再换行），与旁边「一键清空」同高同字号同 weight，行内上下对齐；「从测试结果加入」列表从 20 行降为 10 行高（480dp）、框内滚动；两个「一键清空」分清：加入列表旁边的那个只清空「从测试结果加入」里显示的本次测试结果（不动订阅列表、不动测试结果输出框和输入框）；「更新订阅」旁边新增一个「一键清空」，这个才是清订阅列表的（清订阅里的优选 IP）。

## 使用方法

1. 打开 App，把目标列表粘贴进输入框（每行一个 IP 或域名，可带端口）。
2. 点「开始测试」，等状态栏显示完成。
3. 点「导出结果（仅成功目标）」，复制或分享结果。
4. 想中途停下，点「暂停」，已测的照常显示和导出。

## 优选订阅（v1.3）

把测好的优选 IP 变成一条固定不变的订阅链接，填进客户端（Clash、sing-box）一次，一直能用。

### 原理

订阅的每条节点都是你的节点模板克隆出来的，只把服务器地址换成测好的优选 IP；模板的端口、SNI、Host、路径等一个字不动，SNI 保持模板域名不变。订阅文件存在你自己的 SECRET Gist 里（Clash 一份 `clash.yaml`，sing-box 一份 `singbox.json`），链接第一次更新后生成，此后永不换，只换里面的节点。

### 用法

1. 在订阅区「节点模板」里粘贴一条 VLESS 节点链接（VLESS WS+TLS），点「保存模板」。模板只保存在本机。
2. 在订阅区「GitHub 令牌」里粘贴一个 GitHub Personal Access Token，点「保存令牌」。令牌只保存在本机。建令牌的方法：GitHub → Settings → Developer settings → Personal access tokens (classic) → Generate new token，只勾 `gist` 权限。
3. 把优选 IP 加进订阅列表：测试结果里每条成功结果旁都有「加入订阅」按钮（也可以点「把本次成功结果全部加入订阅」），或在「手动加入优选 IP」里每行粘贴一个 IP 或 `IP:端口`。列表可逐条删除，自动去重。
4. 点「更新订阅」。第一次更新时，App 会用你的令牌新建一个 SECRET Gist，把两份订阅写进去，并把两条订阅链接显示在界面上（各带复制按钮）；以后每次更新只改这个 Gist 里文件的内容，链接不变。
5. 把显示的两条订阅链接分别填进 Clash、sing-box 客户端，以后每次加了新 IP 再点「更新订阅」，客户端刷新订阅就能拿到最新节点。

### 注意事项

- 节点端口、SNI 等全部取自模板，只换服务器地址；想换模板就重新粘贴一条保存。
- 订阅链接是第一次更新后才生成的，生成前界面上显示“还没创建订阅”。
- 模板、令牌、Gist ID、IP 列表全部只保存在本机，不会上传到任何服务器；公开仓库里只有工具本身，没有你的订阅地址和凭证。
- 如果更新失败，界面状态行会写原因：401 是令牌不对或已过期，403 是令牌没给 `gist` 权限；如果 Gist 被删了，下次更新会自动重新建一个。
- v1.4：更新订阅后 App 会立刻用 no-cache 请求刷一次两条订阅链接的 CDN 缓存，客户端刷新一般能立刻看到新 IP；如果当时网络不通，状态行会写“客户端约 5 分钟内同步”，等缓存过期就能看到。

## 下载安装

- 推荐：打开本仓库的 Releases 页，下载最新版 APK，手机上点开安装（需允许“安装未知应用”）。
- 备用：打开本仓库的 Actions 页，找最新一次 Build APK，在 Artifacts 里下载 `app-debug-apk`，解压得到 APK 再安装。

## 自己编译

- 用 Android Studio 打开本仓库，点 Run 即可；或
- 把代码推到自己 fork 的仓库，GitHub Actions 会自动跑 `gradle assembleDebug` 编译出 APK。

## 隐私说明

- App 不注册、不登录、不收集你的个人信息。
- 测试请求发给目标本身和 Cloudflare 的公开测速域名（`www.cloudflare.com`、`speed.cloudflare.com`），只为测延迟和下载速度；你的输入列表不会上传到任何服务器。
